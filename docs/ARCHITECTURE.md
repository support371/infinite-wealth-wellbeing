# Architecture

The platform is structured as a governed digital operating system, not a static website.

## Layers

1. Public website: identity, trust, services, resources, donation and member pathways.
2. Member ecosystem: onboarding, responsibilities, benefits, support and account history.
3. Practitioner ecosystem: application, standards, verification, profile guidance and service setup.
4. Admin operations: queues, content, applications, records, donations and support routing.
5. Super admin: roles, environments, integrations, audit logs, domain readiness and incident controls.

## Rule

Business-critical workflows must be persisted through API/database layers and audited before production use.
